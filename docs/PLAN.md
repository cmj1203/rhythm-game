# AI 노래 리듬게임 기획서 (v0.2)

작성일: 2026-10-01 / 상태: 방향 확정, "9. 정해야 할 것"만 남음

v0.1에서 바뀐 점: 게임 안에서 노래를 생성하는 기능은 보류. 노래는 운영자(나)가 밖에서 AI로 만들어 mp3로 올린다. 보컬 있는 노래를 쓴다.

## 1. 한 줄 정의

**"내가 AI로 만든 노래들을 골라서 플레이하는 웹 리듬게임."**

| 항목 | 결정 |
|---|---|
| 노래 | 내가 Suno 등에서 만든 mp3를 직접 올림 (보컬 있는 곡) |
| 채보(노트) | 곡을 올릴 때 도구가 분석해 자동 생성 |
| 플랫폼 | 웹 (PC 키보드 + 모바일 터치) |
| 목표 수준 | 정식 서비스 / 포트폴리오급 |
| 비용 | 0원 (API, 서버, 로그인 없음) |
| 소스 코드 | 공개 (확정) |

## 2. 흐름

**플레이하는 사람**

```
[처음 화면: 인트로와 제목] -> [하는 법] -> [곡 목록: 난이도 탭에서 곡 선택] -> [플레이] -> [결과: 100점 만점 점수] -> [곡 목록]
```

**곡을 추가하는 나**

```
[AI로 노래 만들기] -> [mp3를 프로젝트 폴더에 넣기] -> [채보 도구 실행 (명령어 한 줄)]
                  -> [채보 파일 자동 생성] -> [곡 목록에 나타남]
```

## 3. 게임 규칙 (핵심 플레이)

| 항목 | 내용 |
|---|---|
| 이름과 컨셉 | **라이브캔버스**, 리듬 + 그림 (2026-10-02 저녁, 사용자 결정). "한 땀"은 리듬게임 같지 않은 이름이라 바느질 컨셉과 함께 버렸다. 바늘은 크레파스로 바꿨다. 인트로는 세 가지(A 보기, B 치기, A+B)를 비교한 뒤 A+B(박자에 맞춰 누를 때마다 제목이 한 글자씩 써짐)로 정했다가, 누르는 부분을 빼서 지금은 크레파스가 제목을 저절로 한 글자씩 쓴다. 플레이 화면의 선도 크레파스로 그은 한 줄(종이 결, 판정은 진하기와 굵기, Miss는 낙서)로 바꿨다(2026-10-03) |
| 이전 컨셉 | "한 땀" (2026-10-02 결정, 같은 날 저녁에 바꿈): 바느질. 바늘이 실을 끌고 가며 한 땀씩 꿰매고, 판정이 땀 모양으로 남고, 곡이 끝나면 완성된 자수를 보여 준다. 1단계(바늘과 실, 땀 모양, 끝날 때 자수 보여 주기)와 "자수가 그림이 된다"(아스트라가 그린 한붓그리기 그림. 채보마다 후보 3장 중 리듬에 가장 잘 맞는 그림이 자동으로 정해지고, 곡이 끝나면 실이 당겨져 그림이 완성됨), "단조로움 줄이기"(구간마다 실 색과 화면 거리·기울기 변화, 콤보에 따라 커지는 효과, 리듬에 따른 땀 굵기) 완료. 남은 것: 실제 곡 구조(후렴 등)를 분석해 구간 나누기, 자수첩(지난 결과 모아 보기), "한 땀" 로고 메인 화면 |
| 방식 | 원버튼 길 따라가기: 크레파스가 마지막으로 그린 자리를 중심으로 돌고, 크레파스 끝이 다음 칸의 흰 고리에 닿는 순간 키를 누르면 건너간다 (얼불춤 방식 참고). 노트 사이 간격이 길의 꺾이는 각도가 된다. 크레파스는 한 박에 반 바퀴씩 일정하게 돈다 (2026-10-03: 길이 그림을 따라 꺾이는 각도에 따라 도는 빠르기가 달라져 화면이 노래와 따로 놀던 것을 고침). 2026-10-02에 반원 5키에서 변경 |
| 거쳐 온 방식 | 4레인 낙하형 -> 7키 반원 -> 5키 반원(스쿠페스 참고, git 커밋 `20c8d8a`에 저장) -> 지금 |
| 그림 | 원작의 이름, 그림, 맵은 쓰지 않는다. 그림은 아스트라(GPT-6 Astra)가 새로 그린 한붓그리기 아트만 사용 (`public/pictures/`). 사용자가 보여 준 참고 그림은 스타일만 참고하고 베끼지 않음 |
| PC 조작 | 아무 키 하나, 또는 마우스 클릭 |
| 모바일 조작 | 화면 아무 곳이나 탭 (동작은 만들어 둠, 폰 화면 크기 확인은 2단계) |
| 놓쳤을 때 | 게임이 끝나지 않고 Miss만 찍히고 다음 칸으로 넘어감 (원작처럼 바로 실패하는 모드는 나중에 선택 사항으로 검토) |
| 디자인 | 단순한 어두운 화면. 바뀌는 것은 모두 노래(구간)나 내 연주(타격, 콤보)에서 나온다 (`DESIGN.md`). 화려한 무대 디자인은 시도했다가 사용자 의견으로 걷어냈고, 그 뒤 너무 단조롭다는 의견으로 구간 변화와 콤보 효과를 더했고, 구간마다 카메라가 움직이게 함 (2026-10-03) |
| 노트 종류 | 한 줄 리듬 (누르는 시간만 있음). 동시치기와 롱노트는 이 방식에 없어서 뺌 |
| 판정 | Perfect(±40ms) / Great(±80ms) / Good(±120ms) / Miss |
| 점수 | 판정별 점수 + 콤보 보너스. 결과 화면에서는 판정 정확도를 100점 만점으로 보여 준다(전부 Perfect일 때만 100점) |
| 난이도 | 곡마다 하나 (2026-10-03, 사용자: 곡별 난이도를 없애고 난이도별로 곡을 나눔). 채보 도구가 빠르기로 정하고(105 BPM 미만 Easy, 125 BPM 이상 Hard) 손으로 바꿀 수 있다. Easy: 박자마다. Normal: 박자 + 센 반 박자. Hard: 반 박자마다 + 센 잔박. 지금은 Easy 4곡, Normal 3곡, Hard 3곡 |
| 곡 길이 | 제한 없음. 처음 테스트는 1~2분 곡 추천 |

## 4. 노래

| 항목 | 내용 |
|---|---|
| 만드는 곳 | Suno, Udio 등 AI 음악 서비스 (게임 밖에서) |
| 형식 | mp3 |
| 곡 정보 | 제목, 아티스트(또는 만든 도구), 커버 이미지(선택) |
| 보관 | 프로젝트 안 `songs` 폴더. 곡마다 폴더 하나 (mp3 + 채보 + 정보) |

**주의 (권리)**: 게임을 공개 배포할 계획이므로, 노래를 만든 서비스에서 상업 이용이 허용되는 요금제로 만든 곡인지 확인한다. 보통 무료 요금제로 만든 곡은 상업 이용이 안 된다. (서비스별 약관은 곡을 올리기 전에 직접 확인 필요)

**만들 때 팁**: 프롬프트에 BPM을 적고("128 BPM"), 드럼 비트가 뚜렷한 장르를 고르면 자동 채보 품질이 좋아진다.

## 5. 자동 채보

**무엇**: 노래 파일에서 박자와 "소리가 터지는 순간"을 찾아 노트 위치로 바꾸는 과정.

**언제**: 플레이할 때가 아니라 **곡을 추가할 때 한 번만**, 내 컴퓨터에서 실행한다. 게임은 이미 만들어진 채보 파일만 읽는다.

이렇게 하는 이유:
- 플레이어 기기에서 분석하지 않으니 로딩이 빠르고 폰에서도 가볍다.
- 자동 결과가 마음에 안 들면 채보 파일을 손으로 고칠 수 있다.
- 소스를 공개하기로 했으므로 v0.1에서 걸렸던 essentia.js의 AGPL 조건(소스 공개 의무)은 더 이상 제약이 아니다. 분석 도구는 라이선스가 아니라 채보 품질로 고른다.

| 단계 | 하는 일 |
|---|---|
| 1. BPM/비트 추출 | 곡의 빠르기와 박자 격자를 구한다 |
| 2. 온셋 검출 | 드럼, 멜로디가 시작되는 순간들을 찾는다 |
| 3. 격자 맞춤 | 온셋을 가장 가까운 박자(1/2, 1/4박)에 붙인다. 어긋난 노트를 없애는 핵심 단계 |
| 4. 밀도 조절 | 곡의 난이도(Easy/Normal/Hard)에 맞는 만큼 소리가 센 자리만 남긴다 |
| 5. 레인 배치 | 음역(낮은 소리=왼쪽, 높은 소리=오른쪽) + 같은 레인 연타 방지 규칙 |

**보컬 곡 대응**: 목소리는 시작점이 흐릿해서 박자 검출을 방해한다. 드럼 등 타격 소리만 뼈대 박자로 쓴다.

**보류 (2026-10-01 실제 곡 테스트 결과)**: 보컬 멜로디를 Hard 노트로 넣는 기능은 뺐다. 단순 검출 방식은 목소리 떨림(비브라토)에 반응해 박자와 무관한 헛노트를 만든다. 넣으려면 음높이를 추적해 음표 단위로 나누는 방식이 필요하다. 지금 Hard는 8분음표에 강한 엇박(16분음표)을 더한 구성이다.

**도구**: 박자는 Beat This!(박자 분석 모델, MIT 라이선스)로 찾고, 타격 소리 세기와 박 다듬기는 Python의 librosa로 한다. 결과는 곡의 난이도와 "누르는 시간" 목록(JSON)으로 저장한다.

**박자 분석기를 바꾼 까닭 (2026-10-03)**: 처음에는 librosa의 박자 추적만 썼다. 사용자가 폰에서 해 보고 "노래와 게임이 안 맞는다, 노트가 박자와 상관없는 곳에 있다"고 해서 곡마다 재 보니 10곡 중 6곡에서 박을 잘못 짚은 구간이 있었다. Hyperfun은 곡의 대부분에서 저음(쿵)이 노트의 반대쪽 박에 실렸고, Pixel Peeker Polka는 곡의 4분의 1이 통째로 엇박이었고, Circles, Swansong, Funkorama는 중간에 반 박씩 미끄러졌고, 3박자 곡인 Release는 박을 하나씩 건너뛰어 마디와 어긋났다. 소리가 세게 나는 곳만 보고 박을 따라가는 방식이라, 엇박에 화음이 세게 나는 곡이나 중간에 쉬는 곡에서 엇박으로 넘어간 것이다. Beat This!로 바꾸고 채보 30개를 모두 다시 만들었다.

**브라우저마다 다른 mp3 디코딩**: 같은 mp3라도 브라우저마다 앞머리의 빈 소리를 잘라 내는 양이 다르다(재 본 값: 정보 머리말이 없는 5곡에서 크롬 0.012초, 사파리 계열 0.025초). 채보에 "소리가 또렷하게 터지는 순간" 8개의 시간(`anchors`)을 적어 두고, 게임이 곡을 불러올 때 그 순간들을 다시 찾아 차이만큼 채보를 옮긴다.

**화면이 박자를 싣게 하기 (2026-10-03)**: 채보를 고친 뒤에도 사용자가 노트북에서 "완전 노래랑 따로 논다"고 했다. 소리와 판정 시간은 맞았다(유선 헤드폰, 크롬, 채보와 타격 소리의 차이 수 ms). 어긋난 것은 화면이었다. 길이 그림을 따라 꺾이는 각도만큼 크레파스가 도는 각도가 달라져서, 박자가 일정해도 한 박에 90~270도를 돌았다(박자가 일정한 Test Beat에서 칸의 58%가 180도에서 20도 넘게 벗어남). 길이 어떻게 꺾이든 한 박에 정확히 반 바퀴를 돌도록 바꿨다. 노트 자리가 노래와 맞는지 귀로 확인하려면 주소에 `?tick`을 붙인다(노트마다 톡 소리).

## 6. 기술 구성

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Vite + TypeScript | 서버가 필요 없어져서 가장 가벼운 구성으로 충분. 회사 레포에서도 쓰는 도구 |
| 게임 화면 | Canvas 2D (이펙트가 필요해지면 PixiJS) | 노트 수백 개를 60fps로 그리기에 충분 |
| 오디오/싱크 | Web Audio API | 오디오 시계 기준으로 판정해야 박자가 밀리지 않는다 |
| 채보 도구 | Python 스크립트 (Beat This! + librosa) | 곡 추가할 때 내 컴퓨터에서만 실행 |
| 배포 | GitHub Pages (2026-10-03). `main`에 푸시하면 자동으로 빌드해서 https://cmj1203.github.io/rhythm-game/ 에 올린다 | 파일만 올리면 되고 무료. 무료 요금제는 공개 레포만 되어서 레포를 공개로 바꿈 |
| 서버/로그인/DB | 없음 | 랭킹을 넣을 때만 추가 |

## 7. 개발 단계

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| 0. 코어 | mp3 1곡 -> 채보 도구 -> PC에서 키보드 플레이 (처음 4키, 지금 7키) | 직접 쳤을 때 "박자가 맞다"고 느껴진다 (기능 완료, 체감 확인 대기) |
| 1. 게임 틀 | 곡 목록, 난이도 3종, 결과 화면 | 곡을 고르고 한 판을 끝내고 점수를 본다 (2026-10-01 완료) |
| 2. 모바일 + 보정 | 터치 조작, 싱크 오프셋 조절 | 폰에서도 판정이 어긋나지 않는다 |
| 3. 완성도 | 타격 이펙트, 롱노트, 디자인, 최고 기록 저장 | 포트폴리오로 보여 줄 수 있는 수준 |
| 4. 공개 | 배포, (선택) 온라인 랭킹 | 다른 사람이 링크로 들어와 플레이 (배포는 2026-10-03 완료, 랭킹은 아직) |
| 보류 | 게임 안에서 AI 노래 생성 | 필요해지면 v0.1 조사 내용으로 재검토 |

## 8. 위험 요소

| 위험 | 대응 |
|---|---|
| 자동 채보가 박자와 어긋난다 | 실제로 일어났고(2026-10-03, 5절) 박자 분석기를 바꿔 고쳤다. 곡을 추가하면 직접 들어 보고, 어긋나면 채보 파일을 손으로 고칠 수 있다 |
| 보컬 때문에 노트가 지저분하다 | 드럼 중심으로 뼈대를 잡고 보컬은 Hard에서만 반영 |
| 모바일 오디오 지연 | 오프셋 보정 화면 제공. iOS는 첫 터치 이후에만 소리 재생 가능 |
| 노래 권리 | 상업 이용 가능한 요금제로 만든 곡만 올린다 |
| 곡이 많아지면 용량이 커진다 | mp3 음질을 적당히 낮추고(128~192kbps), 곡은 선택했을 때만 내려받는다 |
