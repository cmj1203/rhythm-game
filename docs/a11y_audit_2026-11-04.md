# 화면 접근성·모바일 감사 (2026-11-04)

## 범위와 방법

- 대상: 커밋 `1c4a467`(src·index.html 은 main 의 `f3881b3` 와 같다) 의 `index.html`, `src/style.css`, `src/*.ts`. 코드는 고치지 않았다.
- 화면: 타이틀, 튜토리얼(플레이 방법), 곡 선택 메뉴, 설정, 박자 맞추기(calibration), 준비(누르면 시작), 플레이, 일시정지, 게임 오버, 결과.
- 측정 환경: `pnpm build` 후 `vite preview`(포트 4173). Playwright 1.63.0, `chromium.launch()`(옵션 없음, Chromium 153.0.8010.12, headless). viewport 360×640 과 640×360. 결과 화면은 짧은 곡(`?song=the-adventure`, 58초)에서 키를 25ms 간격으로 계속 눌러 도달했다(판정 창 밖의 누름은 벌점이 없다, `judge.ts` `press`).
- 키보드: 각 화면에서 Tab 을 눌러 `document.activeElement` 와 계산된 outline 을 기록했다. 화면 전환 직후의 포커스 위치도 기록했다.
- 겹침: 각 화면에서 스크린샷을 찍어 직접 봤고, `document.documentElement.scrollWidth`, 보이는 요소의 `getBoundingClientRect()` 가 viewport 밖으로 나가는지, 요소별 `scrollWidth > clientWidth` 를 쟀다.
- 대비: WCAG 2.x 상대 휘도 `L = 0.2126R + 0.7152G + 0.0722B`(채널은 `c/12.92` 또는 `((c+0.055)/1.055)^2.4`), 대비비 `(L1+0.05)/(L2+0.05)`. 반투명(`opacity`, `rgb(... / n%)`, `globalAlpha`)은 sRGB 에서 아래 색과 합성한 값으로, `mixColors` 는 코드와 같은 선형 보간으로 계산했다(파이썬 스크립트). 기준: 글자 4.5:1, 큰 글자(24px 이상 또는 18.66px 이상 굵게) 3:1, 그래픽·UI 경계 3:1.
- 스크립트와 스크린샷은 저장소 밖 scratchpad 에만 두었다.

## 1. 키보드·터치 입력

- `src/main.ts:532-540` · 준비 화면에서 Escape 가 아닌 모든 키(Tab 포함)가 `preventDefault` 후 곡을 시작한다. 측정: 준비 화면에서 Tab 한 번에 `#back` 이 숨고 `#pause` 가 나타남(곡 시작), 포커스는 BODY. 키보드로 `곡 선택` 버튼에 갈 수 없다. · Tab(과 Shift+Tab)은 곡 시작에서 빼고, `event.target` 이 버튼이면 넘긴다. 화면에 "Esc: 곡 선택" 안내를 같이 둔다.
- `src/main.ts:521-528` · 박자 맞추기 화면에서 포커스가 BODY 이면 Tab 도 `preventDefault` 되고 누름으로 처리된다. 측정: 결과("다시 해 주세요")가 나온 뒤 Tab 4번 모두 BODY 에 머묾. Enter 도 누름, Escape 는 `cancel()`(값 버림)이라 키보드만으로는 `확인`(측정값 저장)을 누를 수 없다. · Tab 을 막지 않는다. `finish()`(`src/calibration.ts:119-123`)에서 `확인`(없으면 `다시`)에 `focus()` 를 준다.
